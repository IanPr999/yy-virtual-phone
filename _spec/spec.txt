人话版
1 先说出已经确定的那一句
普通做法像先把整篇稿子写完、录完，再把音频交给播放器。实时通话把这段等待拆开：文字生成一小段，确认它不会再改，就交给语音合成；声音出来一小块，就传给浏览器排队播放。
例如回答要说三句话。第一句话开始播放时，第二句话可以正在合成，第三句话仍在生成。它们顺序不变，但不同工序可以同时推进。
文字逐步生成 → 稳定句子 → 音频小块 → 连续播放
这里有两种“流”：文字流负责尽早提供可以说的内容；音频流负责不等整段音频下载完就交给播放器。只有其中一种是流式，另一端仍可能把响应速度拖慢。
不能收到一个字就马上念。半句话、未闭合的声音标签、尚未完成的双语格式，都可能被后续内容补全。实现会保留不稳定的尾部，只放出已经确定的前缀；已经放出的内容不能悄悄改写。
・┈・┈・┈・┈・⊹*:ꔫ:*˖⊹・┈・┈・┈・┈・
2 低延迟来自减少串行等待
“丝滑”不是网络和模型没有耗时，而是尽可能把等待重叠起来，同时让播放不断裂。我们关心两个体验：开口之前等多久，以及开口之后会不会一句一卡。
让下一步提前开始
文字生成和语音消费通过一个小队列连接。前面一句一旦稳定，就开始合成，不等整篇回答完成。音频传输又与浏览器播放重叠。连接尽量复用，减少每轮重复建立连接的开销；预热只能在接口支持时使用，失败不能卡住正文。
留一点缓冲 再按时间轴接起来
音频包到达的间隔并不均匀。播放器先积累少量音频，再把每一块安排到上一块结束的时间点。不能“收到一个包就立刻播放”，否则网络抖动会直接变成耳朵里的停顿。
当前实现用约 0.5 秒音频作为启动缓冲，并保留约 0.05 秒的调度提前量。这是实现参数，不是响应时间承诺：0.5 秒音频可能很快生成，也可能要等更久。短句已经收完时不必硬等到缓冲阈值。
控制提前量 避免越说越积压
后端可以领先播放少量句子，但不能无限生成。当前思路允许最多领先已播完位置两句；浏览器真正播完后再确认，后端继续往前。这样既能衔接，也能在挂断时及时停止无用工作。
必须分别测量首声与连续性
首声等待包含：识别收尾、首段稳定文字、首块语音生成、网络传输、启动缓冲和设备输出。服务端“已发音频”不等于扬声器“已响”。浏览器可以记录音频时间轴开始推进的时刻，最终听感仍需实际设备验收。
这套方法不保证所有路径都一样快。需要工具结果、完整上下文处理或特殊输出格式的路径，可能仍要先拿到完整文本。应明确标注回退路径，而不是把所有场景统称为全链路流式。

3 双语切换是两套独立选择
“我说什么语言”和“对方用什么语言回答”应当独立。例如我说中文，希望听英文回答并看中文释义；或者我用英文提问，希望听中文解释。输入语言交给语音识别，输出语言决定生成和合成的处理方式。
一轮开始时固定语言
在本轮建立时复制语言设置。通话中切换按钮，只影响下一轮，不把正在播放的半句话突然换一种语言。每轮保存自己的语言快照，可以避免异步请求读到后来修改的全局设置。
英文台词与中文释义成对输出
双语输出采用明确的行标记：EN 表示真正要念的英文，ZH 表示对应的中文释义。中文释义只用于显示，不送入语音合成。不要把台词和释义混在一个字符串里，让播放器再去猜。
EN: Take your time.
ZH: 慢慢来。
EN: I am listening.
ZH: 我在听。
流式输出可能在任何位置断开，包括 EN 标记中间。解析器需要攒住未完成的行，确认一组内容稳定后再发布。当前双语思路是先完成基础回答，再流式改写出语言对；已经稳定的前一组先合成，后面的组继续生成。
声音标签也要分开处理：合成文本可以保留接口认可的声音标签，字幕和中文释义去掉这些控制标记。这样听到的是表达效果，看到的是正常台词，不会把“语音模式”之类的说明念出来。
这套方案的适用边界
本文以轮流说话为范围，不实现插话打断。仍然需要支持挂断、断线收尾和防止外放声音触发自答。浏览器语音识别能力存在差异，应单独适配；更换识别实现不需要重写后面的文字与音频流水线。

机读版 实现契约
以下是面向开发者或代码助手的参考规格。代码展示核心算法和接口边界，不是一套复制后即可启动的完整应用。识别、生成、合成、鉴权和网络写入由适配器提供；不得把示例中未实现的函数当作现成依赖。
4 模块与轮次状态
Turn = {
  "id": "opaque-id",
  "input_lang": "zh-CN",
  "output_lang": "en",
  "state": "generating",
  "acked_sentence": 0
}
# create_turn(): authenticate, bind session, snapshot langs
# text_units(turn): async iterator of stable speech units
# tts_pcm(text): async iterator of PCM byte fragments
# send(event): awaited write, bounded buffering
# wait_credit(turn, k): cancellable wait with timeout
先完成会话与轮次绑定，再启动生成和消费任务。每个事件归属于明确的 turn_id；句号 k 从 1 开始，句内音频序号 seq 从 0 开始。过期轮次的事件不能影响当前播放器。
MUST 始终成立的约束
文字发布前缀只能追加，不能撤回重写。句子只能按顺序播放；已播放确认只能单调前进。挂断后，迟到的文本、音频和权限回调都必须被拒绝或释放。
持久化策略是独立契约：允许保存的通话应记录实际发布的稳定内容；不记忆模式不得因此写入对话、音频或后台记忆。不能用取消任务为理由，静默抹掉已经正式播放的内容。
NEVER 用假完成替代实际完成
收到音频结束事件只代表该句传输结束，不能立即回报“播放完成”。网络流结束但没有正常终止事件，也不能记为成功。任何示例都不应自动调用付费合成或打开摄像头、麦克风。

5 稳定文本与音频事件
text_units 必须输出稳定且完整的语音单元。中文可以按句末标点切分，但要先处理括号和控制标签状态；保留尚未闭合的尾部。流结束时经过最终解析再放出剩余正文。不要只靠一个标点正则覆盖所有输出格式。
published = ""
async for snapshot in generated_snapshots:
    stable = parser.stable_prefix(snapshot)
    if not stable.startswith(published):
        raise ValueError("published prefix changed")
    delta = stable[len(published):]
    for unit in parser.take_complete_units(delta):
        await queue.put(unit)
    published = stable
# parser owns incomplete tails; finish() flushes once
for unit in parser.finish():
    await queue.put(unit)
这里的 parser 是有状态适配器：stable_prefix 不提交半个标签；take_complete_units 保存未成句尾部；finish 只能调用一次。队列必须有上限，异常或取消须传递给生产与消费两端。
统一事件结构
{"type":"sentence","turn_id":"t","k":1,
 "text":"Hello.","zh":"你好。","stream":true}
{"type":"audio","turn_id":"t","k":1,"seq":0,
 "sr":32000,"pcm":"BASE64_PCM_BYTES"}
{"type":"audio_end","turn_id":"t","k":1,"chunks":1}
{"type":"end","turn_id":"t","reason":"complete"}
示例用 POST 请求配合 fetch 读取 SSE 数据流。SSE 解析器须支持 UTF-8 字符、行尾和事件分隔符跨网络块；不能把一次 read 当成一个事件。服务端及时刷新事件，必要时发注释心跳；代理层不能缓冲整段响应。
sentence.text 是清理后的显示台词，zh 是可选释义。合成使用内部 speech_text，不能误用 zh，也不能把保留控制标签的合成台词直接当字幕。

6 后端合成与背压
本例音频格式固定为单声道、32 kHz、16 位有符号小端 PCM。网络片段边界不一定落在采样边界；先保留奇数字节尾部，与下一片段拼接，再发送完整采样。
async def aligned_pcm(source):
    tail = b""
    async for fragment in source:
        data = tail + fragment
        n = len(data) & ~1
        if n:
            yield data[:n]
        tail = data[n:]
    if tail:
        raise ValueError("incomplete PCM sample")

async def produce_audio(turn, units):
    async for k, unit in numbered(units, start=1):
        await wait_credit(turn, k)  # k <= acked + 2
        await send(sentence_event(turn, k, unit))
        seq, total = 0, 0
        source = tts_pcm(unit.speech_text)
        async for pcm in aligned_pcm(source):
            total += len(pcm)
            if total > 32000 * 2 * 60:
                raise ValueError("sentence too long")
            await send(audio_event(turn, k, seq, pcm))
            seq += 1
        if seq == 0:
            raise ValueError("empty audio")
        await send(audio_end_event(turn, k, seq))
    await send(end_event(turn, "complete"))
numbered 和事件构造函数是薄适配器；PCM 在事件中编码为 Base64。60 秒是本例单句上限，必须和前端一致。异常分支发送失败终态并结束任务，不得落入 complete。
背压等待、合成请求和网络写入都要有取消信号与超时。播放确认必须校验会话归属、轮次和连续句号，不能直接信任任意大的确认值。该循环逐句合成；低延迟来自工序重叠，不依赖同时请求大量句子的合成。

7 浏览器按音频时间轴播放
在明确的点击动作中创建或恢复 AudioContext。每个 PCM 块转换为 Float32，再安排到同一音频时钟。下面函数只负责排程；缓冲、事件校验和完成确认由外层播放器负责。
function schedulePCM(ctx, bytes, state) {
  if (bytes.byteLength % 2) {
    throw new Error("unaligned PCM");
  }
  const view = new DataView(bytes);
  const n = bytes.byteLength / 2;
  const buf = ctx.createBuffer(1, n, 32000);
  const dst = buf.getChannelData(0);
  for (let i = 0; i < n; i++) {
    dst[i] = view.getInt16(i * 2, true) / 32768;
  }
  const at = Math.max(state.next, ctx.currentTime + .05);
  const source = ctx.createBufferSource();
  source.buffer = buf;
  source.connect(ctx.destination);
  state.pending++;
  state.nodes.add(source);
  source.onended = () => {
    state.nodes.delete(source);
    state.pending--;
    maybeAck(state);
  };
  source.start(at);
  state.next = at + n / 32000;
}
正常连续排程时 next 应领先当前时间；落后时才从“现在加提前量”恢复。不要用 setTimeout 串接音频块，也不要每块创建一个 AudioContext。
缓冲与完成条件
没有已排程的未来音频时，先积累至少 32,000 字节，即 0.5 秒音频；如果该句已收完，则允许不足阈值的短句启动。接收顺序、采样率、累计长度、结束块数都要检查。
只有收到 audio_end、全部块排程完毕且 pending 为 0，才确认本句。取消时先置 canceled，再停止节点，防止 stop 触发 onended 后误确认。清空队列并终止读取，不让旧回调重新开播。

8 双语解析与语言快照
双语解析以完整行和固定 EN／ZH 标记为协议。以下实现假定每组只有一行 EN 和一行 ZH；模型适配器必须保证该格式，协议错误显式失败。更宽松的格式应另设解析状态，不要静默猜测。
class PairParser:
    def __init__(self):
        self.buf, self.en, self.zh = "", None, None

    def line(self, line):
        line = line.strip()
        if not line:
            return []
        if line.startswith("EN:"):
            value = line[3:].strip()
            if not value:
                raise ValueError("empty EN")
            ready = []
            if self.en is not None:
                if not self.zh:
                    raise ValueError("missing ZH")
                ready = [(self.en, self.zh)]
            self.en, self.zh = value, None
            return ready
        if line.startswith("ZH:") and self.en is not None:
            if self.zh is not None:
                raise ValueError("duplicate ZH")
            self.zh = line[3:].strip()
            return []
        raise ValueError("invalid bilingual line")

    def feed(self, delta):
        self.buf += delta
        ready = []
        while "\n" in self.buf:
            line, self.buf = self.buf.split("\n", 1)
            ready += self.line(line)
        return ready
feed 只接收新增文本，不能反复传累计全文。读取到下一条完整 EN 行，才释放前一组；EOF 时先处理 buf 中最后一行，再验证最后一组 EN／ZH 完整并仅释放一次。这里只合成 EN；字幕清理和声音标签处理应在进入播放队列前完成。

9 故障处理与验收清单
失败不能制造第二份回答
在任何声音或稳定台词发布前，允许按明确策略回退。已经发布之后，不能偷偷重新生成一份不同回答并从头念，也不能把先前内容重复塞进队列。应保留已发布前缀，结束本轮并明确返回失败状态。
挂断统一取消生成、合成、事件读取和播放，释放识别资源。每个异步回调检查轮次是否仍有效。思考和播放期间关闭本轮输入入口，避免外放触发自答；不要仅屏蔽正在播放的状态，却允许思考期间开启第二轮。
最低验收条件
01 文本边界：把标点、声音标签和 EN／ZH 标记切在任意网络块之间；输出仍完整，已发布前缀不回退。
02 音频边界：以 1 字节、3 字节和不规则长度喂入 PCM，重组结果与原始字节完全一致；最终奇数字节尾部显式失败。
03 事件完整性：重复序号、跳号、错误采样率、错误轮次、块数不符和缺失结束事件均不能被当作正常完成。
04 播放完成：audio_end 先到而声音仍在播放时，不发送已播完确认；不足 0.5 秒的短句可以正常播完。
05 取消清理：在等待文本、合成、缓冲和播放四个阶段分别挂断，迟到音频不响，旧轮确认不推进新轮。
06 双语切换：输入与输出语言互不覆盖；本轮中途切换只影响下一轮；中文释义不被朗读，声音标签不出现在字幕中。
07 网络抖动：模拟突发到包、慢速到包和暂停恢复，检查缓冲上限、调度间隙与背压等待，不用隐藏错误来假装流畅。
记录能解释体验的时间点
记录识别结束、首段稳定文字、首音频块到达、音频时间轴起播和本轮播放结束。跨端时钟不可直接相减，先做同步或分别测量。报告首声等待和播放中断次数，附网络、设备与回退路径；没有实测数据就不声称“零延迟”或给出毫秒级收益。
